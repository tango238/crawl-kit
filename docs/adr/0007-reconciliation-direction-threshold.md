# ADR-0007: 自動/手動を direction+threshold に畳む

- **status**: accepted
- **date**: 2026-06-27
- **affects**: （reconciliation 全般）

## Context
「方向(トップダウン/ボトムアップ)を選んで自動適用」と「1つずつ手作業で選択」の両方が欲しい。
これを別機能として作ると二重実装になる。また、方向をシステムの宿命にすると硬直する。

## Decision
方向をシステムの宿命にせず reconciler の**モード**に格下げする(git の merge 戦略と同様)。
「自動 or 手動」は排他モードではなく、`direction`(intent 優先 / code 優先)と `threshold` の
**二つのパラメータ**に一本化する。閾値以上は選んだ方向で自動、未満は手作業キューへ。
さらにマッチの根拠は**単一スコアにせず Evidence ベクトル**で持ち、人が「なぜ」を見て即決できる
ようにする。判断は registry に焼き込み、2回目以降は新規・変更だけを聞く。

## Consequences
- 機能を二つ作らず一つで済む(これ自体が狙った「シンプルさ」)。
- 方向を概念単位で ADR が上書きできる(グローバルな宿命にしない)。
- reconciler が状態を持つ設計になる(registry が人の判断の蓄積になる)。

## Alternatives considered
- 自動モードと手動モードを別実装: 二重実装・分岐の温床。退けた。
- 単一スコアでマッチ: 「0.82 似てる」は人が直せない。Evidence ベクトルを採った。
